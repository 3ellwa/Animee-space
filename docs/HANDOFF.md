# Handoff: animee + cinemee (November 21, 2026)

Everything needed to pick this project up cold. For what changed when, see `docs/CHANGELOG.md`.

## What this is

**One Cloudflare Worker, one repo, two sites:**

| Site | Address | Catalogue | Brand colour | Database |
|---|---|---|---|---|
| **animee** (anime) | https://animee.space | Tenrai (Jikan-style, MAL ids) | Lime `#C6FF3D` | D1 `animee-space` (binding `DB`) |
| **cinemee** (movies + TV) | https://cinemee.animee.space | TMDB | Red `#FF3D52` | D1 `cinemee` (binding `CINEMEE_DB`) |

The **address decides the site** (`functions/_lib/site.js`: `siteOf()` / `siteEnv()`). cinemee swaps in its own
database, so accounts, lists, reports, requests and pop-up subscriptions never mix. Both sites run the same
front-end code; `public/js/site.js` exposes `IS_CINEMEE` / `BRAND` and the wording, options and features
switch on that.

- Repo: GitHub `3ellwa/Animee-space`, branch `main`.
- **Deploy = push to `main`.** Cloudflare Workers Builds builds and deploys in about a minute. Don't use
  `wrangler deploy` by hand.
- Both custom domains are attached to the Worker `animee-space` (Cloudflare → Workers → animee-space →
  Domains & Routes). `cinemee.animee.space` was added through the API on Nov 21.

## Servers (what visitors see → real source)

Names are deliberately neutral; ids stay real in settings, reports, logs and /admin
(`BUILTIN_PROVIDERS` / `CINEMEE_PROVIDERS` in `providers/registry.js`).

**animee** (tried in this order, preferred server first):
1. **3ellwa** = MegaPlay (sub/dub). Resumes and auto-skips via MegaPlay commands; fullscreen handshake.
2. **Rem** = animeembed.com (sub/dub, MAL id; `start`, `autoSkip`, lime `accent`; postMessage `{channel:'animeembed', version:1, event, data}`, commands play/pause/seek; operator may show ads; refuses sandboxing).
3. **Kaze** = AnimeParadise (sub, direct HLS in our own `<video>`, no ads).
4. **JoJo** = VidNest (sub/dub, AniList id looked up in the browser).
5. **Hoshi** = TryEmbed (sub/dub, AniList id; blocks automated browsers, fine for real visitors).
6. **Ram** = aniembed.se (sub/dub, AniList id; `t`, `lang`; postMessage `{source:'aniembed', version:1, name, data}`, progress every 5 s; commands `{type:'command', name, data}`).

Rem and Ram are checked before the fallback uses them (Rem: 404 for unknown shows; Ram: "Couldn't load the player" for missing episodes), and in the browser a Rem/Ram player that never says "ready" within 25 s counts as failed. Don't rename them Sora/Yuki: aniembed.se has internal servers with those names.

**cinemee**:
1. **Orion** = vidnext.pro (red theme, `startAt`, progress messages, seek; Arabic subtitles). Best one.
2. **Nova** = VidNest (Arabic subtitles).
3. **Atlas** = EmbedMaster (`embedmaster.link`, dark skin; accepts `sub_url[]` subtitle files).
4. **Vega** = vidsrc.to (subtitles in many languages incl. Arabic, in its own menu).
5. **Lyra** = VidCore (lots of ads, so last).

**Tried and dropped:** VidLink for anime (its anime player says "couldn't find this episode" for everything,
Nov 21; movies work) · CodeSpecters/NexStream (domain-locked API key that expires every 30 days) ·
AniNeko (dead in October).

## MegaPlay tricks (learned from hianime.ms, see docs/HIANIME-NOTES.md)

Commands are sent as **JSON strings** to `https://megaplay.buzz`:
- `{"event":"seek","time":N}` — resume / Start over / arrow keys.
- `{"cmd":"SKP_DATA","auto":true|false}` — its own intro/outro skip.
- Fullscreen handshake: it asks `getFullscreenState`; answering `{megaFullscreenState:bool}` makes its
  fullscreen button send `toggleFullscreen`, so our whole player box goes fullscreen (Up next stays
  visible). **Not answered on touch screens** (it would break rotate-to-landscape).
- It sometimes reports `error` and then recovers: we wait 5 s for playback before switching servers.

Progress messages understood by `player.js`: MegaPlay `time`/`watching-log`/`complete`; TryEmbed and
VidLink-style `PLAYER_EVENT`; vidnext/VidNest `source:'vidnest-player'`; EmbedMaster
`source:'embedmaster_player'`; VidCore `vidcore:*`. Origin and frame window are always checked.

## Secrets and keys (Cloudflare → Worker → Settings → Variables and Secrets)

| Secret | What | How to (re)set |
|---|---|---|
| `SESSION_SECRET` | signs login cookies | `npx.cmd wrangler secret put SESSION_SECRET` |
| `TMDB_TOKEN` | TMDB "API Read Access Token" for cinemee | `npx.cmd wrangler secret put TMDB_TOKEN` |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | Web Push | `node scripts/setup-push.mjs` (`--force` replaces; devices must re-enable) |
| `ADMIN_KEY` | /admin page | `node scripts/set-admin-key.mjs` (rotated Nov 21) |
| `OMDB_KEY` | optional: IMDb / RT / Metacritic scores on cinemee | free key from omdbapi.com, then `npx.cmd wrangler secret put OMDB_KEY` |

On Windows PowerShell use `npx.cmd` (the `npx.ps1` wrapper is blocked by the execution policy).
Local development reads the same names from `.dev.vars` (git-ignored).

## Durable Objects

- `PARTY` → class `PartyRoom` (exported from worker.js), migration tag `v1` (`new_sqlite_classes`). One room per site + party code. Routed in worker.js before the API wrapper (a WebSocket upgrade can't be re-wrapped).

## Data (D1)

Same schema in both databases (`migrations/0001-0004`): `users`, `library` (one row per show, ids are plain
numbers), `reports`, `requests`, `push_subs`, `push_follows`, `push_shows`. Tables 0002–0004 also create
themselves on first use. `library.s` packs: list status (bits 0–2), favourite 8, sub/dub chosen 16, dub 32,
following 64, your rating 1–10 in bits 7–10. `users.prefs`: playback bits 1/2/4/8, list sharing 16 (all) / 32 (favourites).
Tables created on first use: `errors`, `plays`, `subs`, `notice`, `requests`, `reports`, push tables.

- cinemee ids: TMDB id × 10 + 1 (movie) / + 2 (TV). TV episodes are numbered straight through the aired
  seasons; each keeps `season`/`episode` for the player.
- Apply migrations: `npx.cmd wrangler d1 migrations apply <animee-space|cinemee> --remote`.

## Gotchas (each one bit us once)

- **The two sites talk to each other** only through `/api/me/continue` (CORS, exact sibling origin, credentials). Login cookies are host-only, so accounts stay separate. The CSP allows `http://localhost:8787` and `http://cinemee.localhost:8787` for local development.

- **Commit `worker-assets.js`** after `npm run build`; the deploy serves it as committed.
- **Bump `API_VERSION`** in `public/js/api.js` when API answers change shape: browsers keep API answers 10 min.
- **Page cache:** rendered pages are cached at the edge for an hour, keyed by path + shell hash + **site**.
  A cached page goes to browsers as `no-cache`. (cinemee once showed animee's green page from a copy cached
  before it existed; purge by URL via the Cloudflare API if needed.)
- **Local redirects go to production:** `/anime/123` (no slug) redirects to `https://animee.space/...`. Test
  canonical addresses locally (`/anime/52991/frieren-beyond-journey-s-end`).
- **Service worker offline page:** opening a page while `wrangler dev` is still starting shows "you're offline";
  just reload.
- **Views import from app.js and app.js imports the views** (a module cycle). It works because view
  files only declare things at the top level; never run code there that uses something from app.js.
- **Line endings:** the repo stores CRLF. Editing scripts should keep the file's existing line endings.
- **AniList refuses Cloudflare's servers:** AniList lookups (VidNest/TryEmbed ids, AniList import, links) run
  in the browser (`public/js/anilist.js`).
- **hianime.ms** opts out of AI crawling (robots.txt); the study in docs/HIANIME-NOTES.md was reference-only.
