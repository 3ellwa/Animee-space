# Handoff: animee + cinemee (November 21, 2026)

Everything needed to pick this project up cold. For what changed when, see `docs/CHANGELOG.md`.

## What this is

**One Cloudflare Worker, one repo, three sites, one account:**

| Site | Address | Catalogue | Brand colour | Database |
|---|---|---|---|---|
| **animee** (anime) | https://animee.space | Tenrai (Jikan-style, MAL ids) | Lime `#C6FF3D` | D1 `animee-space` (binding `DB`) |
| **cinemee** (movies + TV) | https://cinemee.animee.space | TMDB | Red `#FF3D52` | D1 `cinemee` (binding `CINEMEE_DB`) |
| **mangee** (manga) | https://mangee.animee.space | MangaDex | Neon yellow `#FFE81F` | D1 `mangee` (binding `MANGEE_DB`) |

**Accounts are shared:** they live in animee's database (`USERS_DB` in `siteEnv`), and the login cookie (`am_session`) is set for `animee.space`, so one sign-in works on all three. Each site keeps its own lists, progress, reports, requests and pop-ups in its own database under that account id. (Locally each `*.localhost` address needs its own sign-in.)

**mangee and MangaDex's rules:** credit MangaDex and the scanlation groups (footer + every chapter), honour groups' removal requests, no ads, all API calls and images through our Worker (User-Agent set, no Via header), MangaDex@Home image loads reported to api.mangadex.network. ~5 requests/s per IP, so everything is cached. Licensed series often have no English chapters.

The **address decides the site** (`functions/_lib/site.js`: `siteOf()` / `siteEnv()`). cinemee swaps in its own
database, so accounts, lists, reports, requests and pop-up subscriptions never mix. Both sites run the same
front-end code; `public/js/site.js` exposes `IS_CINEMEE` / `BRAND` and the wording, options and features
switch on that.

- Repo: GitHub `3ellwa/Animee-space`, branch `main`.
- **Deploy = push to `main`.** Cloudflare Workers Builds builds and deploys in about a minute. Don't use
  `wrangler deploy` by hand.
- Both custom domains are attached to the Worker `animee-space` (Cloudflare → Workers → animee-space →
  Domains & Routes). `cinemee.animee.space` was added through the API on Nov 21.

## Servers (what visitors see → real source)

Names are deliberately neutral; ids stay real in settings, reports, logs and /admin
(`BUILTIN_PROVIDERS` / `CINEMEE_PROVIDERS` in `providers/registry.js`).

**Rule (user's, Nov 24):** ad-free servers go first, and on both sites the first is always named **3ellwa** and
the second **JoJo** (names are swapped with whichever server held them). With no server picked by hand, the
first in the list plays (`preferred` defaults to '' in the API and `provider` to '' in `store.js`; browsers that
only had the old 'megaplay' default were reset once via `serverOrderV2`). A server you clicked, or the one that
last played a show, still wins for that show.

**animee** (tried in this order):
1. **3ellwa** = AnimeParadise (sub only, direct HLS in our own `<video>`, no ads; remembers speed/volume per show). Was Kaze.
2. **JoJo** = aniembed.se (sub/dub, AniList id; `t`, `lang`; postMessage `{source:'aniembed', version:1, name, data}`, progress every 5 s; commands `{type:'command', name, data}`). Sandboxed, no ads; first for dub. Was Ram.
3. **Kaze** = MegaPlay (sub/dub). Resumes and auto-skips via MegaPlay commands; fullscreen handshake. Was 3ellwa. The auto-skip setting names it.
4. **Rem** = animeembed.com (sub/dub, MAL id; `start`, `autoSkip`, lime `accent`; postMessage `{channel:'animeembed', version:1, event, data}`, commands play/pause/seek; operator may show ads; refuses sandboxing).
5. **Ram** = VidNest (sub/dub, AniList id looked up in the browser). Was JoJo.
6. **Hoshi** = TryEmbed (sub/dub, AniList id; blocks automated browsers, fine for real visitors).

Rem and JoJo (aniembed.se) are checked before the fallback uses them (Rem: 404 for unknown shows; aniembed: "Couldn't load the player" for missing episodes), and in the browser a player from either that never says "ready" within 25 s counts as failed. Don't name anything Sora/Yuki: aniembed.se has internal servers with those names.

**cinemee**:
1. **3ellwa** = vidnext.pro (red theme, `startAt`, progress messages, seek; Arabic subtitles). Sandboxed, no ads. Was Orion.
2. **JoJo** = VidCore (same player as VidLink). Sandboxed, no ads; its big centre button is the ad layer, so play from its control bar. Was Lyra.
3. **Sirius** = VidFast (`vidfast.vc`, the final host of vidfast.pro; `theme=FF3D52`, `startAt`, `PLAYER_EVENT`; ~40 subtitle languages incl. Arabic). Added Nov 24.
4. **Rigel** = VidLink (`vidlink.pro`, movies/TV only; `primaryColor=FF3D52` without `#`, `startAt`, `PLAYER_EVENT`; Arabic subtitles). Added Nov 24.
5. **Nova** = VidNest (Arabic subtitles; shows a fake "please confirm" ad dialog).
6. **Atlas** = EmbedMaster (`embedmaster.link`, dark skin; accepts `sub_url[]` subtitle files). Most ads: one per click.
7. **Vega** = vidsrc.to (subtitles in many languages incl. Arabic, in its own menu).

**Ad blocking** (`SANDBOXED_HOSTS` in `public/js/player.js`): players that still play inside
`sandbox="allow-scripts allow-same-origin allow-presentation allow-forms allow-orientation-lock"` get it, so the
browser silently blocks their ad tabs, pop-ups and redirects: vidnext.pro, vidcore.org and aniembed.se (tested
Nov 24). Every other host detects the sandbox and refuses to play ("Please disable sandbox" / "Sandbox detected"):
VidFast, VidLink, VidNest, EmbedMaster, vidsrc.to, TryEmbed, MegaPlay, animeembed.com. Don't try to hide the
sandbox from them; retest a host before adding it.
The desktop app blocks ads everywhere (Ghostery). cimanow.cc was looked at and dropped: its servers sit behind an
ad-shortener token and an encrypted page.

**Tried and dropped:** VidLink for anime (its anime player says "couldn't find this episode" for everything,
Nov 21; movies work) · CodeSpecters/NexStream (domain-locked API key that expires every 30 days) ·
AniNeko (dead in October).

## Smart TVs (TV mode)

`public/js/tv.js` (started from `initTv()` in app.js before the first render) + the `html.tv` block at the end of
style.css. On by UA (`detectTv`), by Settings → Display → TV mode (this browser only), or `?tv=1` / `?tv=0`.
Arrows = spatial navigation (`pickNext`: things in line first, then nearest row, then best aligned; left/right
never change rows). Keys (`keyKind`): Back = 461 LG / 10009 Samsung / GoBack / Escape; ⏯ 179/10252 toggles;
LG Play 415, Pause 19, Stop 413 are explicit; ⏩ 417 / ⏪ 412 = ±30 s; channel 427/428 = next/prev episode.
The watch page registers `setMedia({ playPause, setPaused, seekBy, next, prev, playerBox })`; in TV mode the
player box is focusable and the embed iframe has `tabIndex = -1`, so keys always reach us.
`Player.togglePlay()` / `setPaused()` work for our own `<video>`, Rem, aniembed.se and vidnext (`{action:'play'|'pause'}`).
Test on a PC: `http://localhost:8787/?tv=1` with the window at 1920×1080, keyboard only.
**Video on TVs** (user's LG, Nov 24: sound but no picture): TV browsers draw video on a hardware layer that
breaks under page `zoom`, rounded clipping (`border-radius` + `overflow: hidden`), big shadows, blur filters and
fixed effect layers. In TV mode the watch page (`html.watching`) has none of those, OK/Play also goes full
screen (`enterFullscreen({ quiet: true })`), and focus is pulled back whenever an embedded player grabs it.
Settings → Display shows "This browser: LG webOS · Chrome NN" (`browserLabel`) for debugging a TV.
**Limit:** the site's JavaScript uses `?.`/`??` (Chromium 80+), so TV browsers older than about 2022
(LG webOS 6 / Samsung Tizen 6.0 and earlier) won't run it at all. Android TV / Fire TV browsers are current.

## MegaPlay tricks (learned from hianime.ms, see docs/HIANIME-NOTES.md)

Commands are sent as **JSON strings** to `https://megaplay.buzz`:
- `{"event":"seek","time":N}` — resume / Start over / arrow keys.
- `{"cmd":"SKP_DATA","auto":true|false}` — its own intro/outro skip.
- Fullscreen handshake: it asks `getFullscreenState`; answering `{megaFullscreenState:bool}` makes its
  fullscreen button send `toggleFullscreen`, so our whole player box goes fullscreen (Up next stays
  visible). **Not answered on touch screens** (it would break rotate-to-landscape).
- It sometimes reports `error` and then recovers: we wait 5 s for playback before switching servers.

Progress messages understood by `player.js`: MegaPlay `time`/`watching-log`/`complete`; TryEmbed and
VidLink-style `PLAYER_EVENT`; vidnext/VidNest `source:'vidnest-player'`; EmbedMaster
`source:'embedmaster_player'`; VidCore `vidcore:*`. Origin and frame window are always checked.

|---|---|---|

## Durable Objects

- `PARTY` → class `PartyRoom` (exported from worker.js), migration tag `v1` (`new_sqlite_classes`). One room per site + party code. Routed in worker.js before the API wrapper (a WebSocket upgrade can't be re-wrapped).

## Data (D1)

Same schema in both databases (`migrations/0001-0004`): `users`, `library` (one row per show, ids are plain
numbers), `reports`, `requests`, `push_subs`, `push_follows`, `push_shows`. Tables 0002–0004 also create
themselves on first use. `library.s` packs: list status (bits 0–2), favourite 8, sub/dub chosen 16, dub 32,
following 64, your rating 1–10 in bits 7–10. `users.prefs`: playback bits 1/2/4/8, list sharing 16 (all) / 32 (favourites).
Tables created on first use: `errors`, `plays`, `subs`, `notice`, `requests`, `reports`, push tables.

- cinemee ids: TMDB id × 10 + 1 (movie) / + 2 (TV). TV episodes are numbered straight through the aired
  seasons; each keeps `season`/`episode` for the player.
- Apply migrations: `npx.cmd wrangler d1 migrations apply <animee-space|cinemee> --remote`.

## Gotchas (each one bit us once)

- **The two sites talk to each other** only through `/api/me/continue` (CORS, exact sibling origin, credentials). Login cookies are host-only, so accounts stay separate. The CSP allows `http://localhost:8787` and `http://cinemee.localhost:8787` for local development.

- **Commit `worker-assets.js`** after `npm run build`; the deploy serves it as committed.
- **Bump `API_VERSION`** in `public/js/api.js` when API answers change shape: browsers keep API answers 10 min.
- **Page cache:** rendered pages are cached at the edge for an hour, keyed by path + shell hash + **site**.
  A cached page goes to browsers as `no-cache`. (cinemee once showed animee's green page from a copy cached
  before it existed; purge by URL via the Cloudflare API if needed.)
- **Local redirects go to production:** `/anime/123` (no slug) redirects to `https://animee.space/...`. Test
  canonical addresses locally (`/anime/52991/frieren-beyond-journey-s-end`).
- **Service worker offline page:** opening a page while `wrangler dev` is still starting shows "you're offline";
  just reload.
- **Views import from app.js and app.js imports the views** (a module cycle). It works because view
  files only declare things at the top level; never run code there that uses something from app.js.
- **Line endings:** the repo stores CRLF. Editing scripts should keep the file's existing line endings.
- **AniList refuses Cloudflare's servers:** AniList lookups (VidNest/TryEmbed ids, AniList import, links) run
  in the browser (`public/js/anilist.js`).
- **hianime.ms** opts out of AI crawling (robots.txt); the study in docs/HIANIME-NOTES.md was reference-only.
